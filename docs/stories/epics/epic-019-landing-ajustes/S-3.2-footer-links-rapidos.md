# Story S-3.2 — Rodapé "Links Rápidos" com texto sobreposto
**Epic:** EPIC-019
**Status:** Done
**executor:** @dev
**quality_gate:** @dev
**quality_gate_tools:** [tsc, build]

## Contexto

No rodapé do site público (`client/src/pages/Home.tsx`), a coluna "Links Rápidos" (Início,
Projetos e Orçamentos, Sorteios, Produtos, Como Funciona) foi reportada pelo dono do produto
com os itens "Sorteios" e "Produtos" se sobrepondo visualmente (texto ilegível, um por cima
do outro).

## Acceptance Criteria

- [x] AC-01: a coluna "Links Rápidos" do rodapé fica totalmente legível, sem sobreposição
  entre os itens, em qualquer largura de tela (validado em 1280px e 390px)
- [x] AC-02: espaçamento vertical entre os links reforçado de forma explícita e robusta
  (`gap-y-3` + `leading-normal` em cada link), não dependente apenas do valor mínimo de gap
- [x] AC-03: `tsc --noEmit` e `npm run build` passam limpos

## Decisões de implementação (adaptações deliberadas, não invenção)

- O código já usava `flex flex-col gap-2` nessa coluna, o que não reproduziu overlap nos
  testes manuais feitos nesta sessão (telas 1280px e 390px, servidor local). Mesmo assim,
  como o dono do produto reportou o bug visualmente em produção, o espaçamento foi tornado
  mais robusto por precaução: `gap-2` (8px) → `gap-y-3` (12px) e `leading-normal` explícito
  em cada link, eliminando qualquer dependência de herança de `line-height` que pudesse
  causar o problema em fontes/navegadores diferentes dos testados aqui.
- Nenhuma outra coluna do rodapé foi alterada.

## Validação — honestidade de status (regra do dono do produto)

**Testado automaticamente:** `tsc --noEmit` limpo, `npm run build` limpo.

**Testado manualmente por mim:** screenshot do rodapé renderizado (Playwright/Chromium,
`npm run dev` local) em 1280px e 390px de largura — "Sorteios" e "Produtos" aparecem em
linhas distintas e legíveis, sem sobreposição.

**Ainda depende de validação em produção:** o dono do produto reportou o bug em produção;
como não foi possível reproduzir o overlap neste ambiente (DB não disponível, fontes podem
carregar diferente), recomenda-se conferir visualmente o rodapé em produção após o deploy
deste PR. Se o overlap persistir, é sinal de que a causa raiz é outra (ex.: CSS de produção
divergente do build local) e precisa de nova investigação.
