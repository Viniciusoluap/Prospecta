# ARCHITECTURE DECISIONS — Lote 02 (27/10/2026)

- **AD-01 (21) Componente numérico único.** Prospecta `client/src/components/ui/numero-input.tsx`, SF `web/src/components/ui/numero-input.tsx` — `NumeroInput` (valor numérico em reais/unidade, `casas` padrão 2, `prefixo`/`sufixo`, aceita negativo, colagem `1.234,56`/`1234.56`). Máscara pt-BR durante a digitação com cursor estável (iPhone): reposiciona o cursor pela contagem de dígitos à direita. `CurrencyInput`, `PercentInput`, `NumeroBRField`, `AreaInput` passam a ser wrappers do `NumeroInput` (mesma API pública, sem mudar unidade armazenada — centavos continuam centavos). Formatação só na exibição; valor armazenado e precisão interna intactos.
- **AD-02 (04) Engenheiro = Colaborador + perfil.** O papel de autorização continua `colaborador` (herda permissões por módulo sem tocar nas checagens de auth). Nova tabela de perfil de engenheiro (1:1 com usuário: CREA, UF, CREAs adicionais, telefone, endereço completo) + tabela de documentos do usuário (categoria: documento_pessoal, anuidade_crea, carteirinha_crea, outros; arquivo original guardado no banco e servido por rota autenticada; substituir/excluir; ZIP via `fflate.zipSync`). Na UI de Usuários aparece "Engenheiro" como perfil. Selecionar engenheiro em Projetos/Obras/PCI/Incorporação carrega nome + CREA do perfil.
- **AD-03 (06) KML opcional.** Coluna booleana `sem_kml`/`semKml` no estudo + JSON de lotes avulsos (quadra, lote, área, testada, profundidade). Com o flag ligado, os módulos bloqueados só por falta de geometria são liberados; funções geométricas mostram "sem poligonal". Enviar KML depois continua possível.
- **AD-04 (11) Estudos salvos em tabela própria.** Nova tabela de estudos de massa salvos (estudo, nome, versão, origem/versão anterior, parâmetros, cenários, poligonal de referência, cenário escolhido, principal, autor, data, exclusão lógica). As colunas legadas (`mass_scenarios_json`/`selected_scenario_id` e equivalentes SF) continuam sendo espelho do estudo principal para não quebrar Viabilidade/Orçamento/Relatório.
- **AD-05 (15/16) Unidades a partir do cenário.** Unidades ganham chave de origem (`cenário + quadra + lote`) única por estudo, vínculo opcional com lead do CRM, valor, e exclusão lógica (tombstone) — a regeneração por mudança de cenário é idempotente, preserva reservadas/vendidas e não recria excluídas.
- **AD-06 (03) Modelos de PCI versionados.** Tabela de modelos PCI (arquivo original no banco, formato xls/xlsm/xlsb, versão, atual) + tabela de PCIs geradas por obra (dados do formulário, XLS e PDF gerados, autor, data). Escrita em XLS via `PastaBiff8` existente; XLSM via edição das partes XML do zip (preserva macros); XLSB só leitura (mapeamento) — gerar exige versão XLS/XLSM do modelo, informado na tela. Envio de PCI atual intacto.
